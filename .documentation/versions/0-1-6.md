# lore 0.1.6

The first version tagged for a GitHub release (`v0.1.6`, commit eee085c4,
2026-11-24). Everything after 0.1.5 (e78904ee) is in it.

**The release did not publish.** On GitHub, the tests passed and the Linux
builds ran, but both macOS jobs were cancelled before they started:
GitHub no longer has the `macos-14` machines the workflow asked for. The
last job needs every build, so no release page was made. The workflow now
uses `macos-latest`; the next tag (v0.1.7) releases it.
Built with rustc 1.97.0, edition 2024 (rustc 1.88 or newer is needed:
ratatui 0.30.2 asks for it), ratatui 0.30.2, unicode-width 0.2, ruzstd 0.8
(zstd 0.14 to build) and ureq 3.5 with rustls.

## What a release holds (once one is published)

| File | For |
| --- | --- |
| `lore_0.1.6-1_amd64.deb`, `_arm64.deb` | Debian, Ubuntu, Mint, Pop!_OS: `sudo apt install ./lore_0.1.6-1_amd64.deb` |
| `lore-0.1.6-1.x86_64.rpm`, `.aarch64.rpm` | Fedora, RHEL, Rocky, Alma, openSUSE |
| `lore-v0.1.6-x86_64-unknown-linux-musl.tar.gz`, `aarch64-…` | any Linux: a static binary |
| `lore-v0.1.6-aarch64-apple-darwin.tar.gz`, `x86_64-…` | macOS, Apple Silicon and Intel (not signed) |
| `SHA256SUMS` | every file's checksum |

Each package and tarball has the binary, `man lore` and the bash, zsh
and fish completions. The binary is static on Linux, so the packages
depend on nothing.

## What is new since 0.1.5

**Keys**
- **The jumper, Space:** in the list, the next letter or group (recipes,
  #, A, B, C… and back to the top); on a page, the next section (VERSION,
  HOW TO USE, RELATED, FILES, INTERNET, MANUAL), back to the top after the
  last.
- **`lore NAME` is the whole app:** ← or Esc on the page go back to the
  list, every key works, Esc in the list quits. Before, closing the page
  quit.
- **Settings on the about screen (`+`):** Colours (Enter, or `p`, opens the
  palette picker over it), Internet on or off, History read or not. ↑↓
  choose, Enter changes it at once and saves it in the settings file. `p`
  works there only now; the list and pages no longer take it.

**Pages**
- **Recipes:** 100 short task pages that chain commands, under their own
  group in the list. Most are the terminal tasks with the most-viewed
  Stack Overflow questions: find files containing a text, copy files to a
  server, send output and errors to a file, ssh keys, free disk space, what
  is using a port. A recipe's page is STEPS, USES (the commands it uses,
  each a page) and NOTES. They are Markdown files in `recipes/`, checked
  by `build.rs`.
- **INTERNET:** `● internet` on the search bar, green when cht.sh can be
  reached and red when not (or turned off). Each command's page gets an
  INTERNET section before MANUAL with the command's community cheat sheet
  from cht.sh, fetched in the background and kept a day in
  `~/.cache/lore/internet/`.
  - It is raw text behind a `│` bar, every control, escape and invisible
    character taken out. lore never turns it into links, never offers it
    to `c` and never runs it, and the section always says it can be
    changed by anyone, without checks.
  - lore asks as `lore/0.1.6 (plain text; like curl)`, since cheat.sh
    sends plain text only to clients it knows; an HTML answer is a failure.
  - Turned off, there is no request at all.
- **Pages other programs ship:** a program can install
  `/usr/share/lore/content/NAME.md` (translations in `i18n/<lang>/`), used
  for a command lore has no page for. Only your own folder,
  `~/.local/share/lore/content/`, can replace a built-in page.
- **`lore check FILE…`:** the check every page read from a folder must pass,
  or it is not shown. Errors: a title that is not the file's name, escape
  or control characters, invisible or reordering characters, HTML or
  script, an example that runs a download (`curl … | sh`), over 64 KB, not
  UTF-8. Odd links are warnings. Invisible and reordering characters are
  also taken out of every page shown, the built-in ones too.

**Command line**
- **`lore explain "tar -xzvf a.tgz"`:** each word of a command line and what
  it means, offline. Flags come from the program's man page: joined flags
  are split, `--opt=value` is read, and `tar xzf` is understood. Pipes and
  lists are explained command by command, along with redirections, and
  with `sudo`, `env` and `xargs` the command they run.
- **Shell completion:** `lore gi<Tab>`, `lore git <Tab>` (the subcommands),
  recipe titles word by word, `lore explain tar --<Tab>` (tar's flags). With
  nothing to offer, file names. The scripts are in `completions/` and call
  `lore --complete`; the packages install them, and
  `lore --completions bash|zsh|fish` prints one.

**Releases and checks**
- **A release is a tag:** `git tag v0.1.6 && git push origin v0.1.6`. The
  notes are the version's CHANGELOG section, or `[Unreleased]` when it has
  none.
- **The musl builds** compile ring (TLS) with clang, set in the workflow.
- **`ci.yml`:** fmt, clippy, tests, the constants rule, a release build, and
  a run of the binary on `--print`, `explain` and `--complete`.
- **`docs.yml`:** the docs' own links, offline, and `man/lore.1` through
  `groff -ww`.
- **`scripts.yml`:** shellcheck and the content scripts.
- All three run on pushes to main and on pull requests that touch what
  they check.
- **`packaging/`:** an AUR build file (`lore-tui`, from source) and a
  Homebrew formula (the release binaries, for a tap
  `guhhammer/homebrew-tap`). After a release, `packaging/update.sh 0.1.6`
  puts the version and checksums in both. Publishing them is by hand.

## How it was checked

- **`cli/make`:** fmt, clippy with warnings as errors, 265 tests, and the
  debug and release builds. All green at the release commit.
- **The tests without the machine's tools:** with `man`, `whatis` and the
  package managers off the PATH, as on a bare CI runner, all 265 pass.
- **By hand in tmux:**
  - Space through the list (recipes, #, A) and through a page's sections.
  - `lore git commit`: ← back to the list, ↓ moves it.
  - The `+` settings: Internet off (red dot, `internet = off` written)
    and on again (green), History off and on, Colours opening the picker
    over `+`, and the palette saved. This used a scratch config folder.
  - `p` does nothing outside `+`.
  - The INTERNET section showing cht.sh's text with the reminder, and
    nothing fetched with the internet off.
  - Bash completion with a real Tab.
- **`lore check`** on a page crafted with every attack: each caught.
- **The workflows' steps,** run locally: the constants grep, the binary's
  smoke run, lychee offline on the docs, groff on the manual, shellcheck,
  and the Python parse.
- **The `.deb`:** built from the static x86_64 binary the way the release
  does. It holds the binary, the man page and the three completions, and
  `apt-get -s install` accepts it.
- **`packaging/update.sh`:** run against a fake release on disk; it filled
  the version and all four checksums. The formula passes `ruby -c`.

## Fixed while preparing this version

- **The minimum Rust** said 1.85, but the locked dependencies need 1.88. It
  says 1.88 now, and clippy's two suggestions for it were applied.
- **The bash completion** read each candidate as a file pattern, so `[`, a
  command, could turn into file names. It uses `mapfile` now.
- **`lore check`** took `scheme <script.scm`, a redirection, for HTML.
  It now matches only a real tag.
- **Cargo.lock** says 0.1.6, like `Cargo.toml`; 0.1.5's said 0.1.4.
- **cheat.sh** answered with a web page until lore said it was a
  curl-like client.

## Open

- **The workflows on GitHub, at this tag:** `ci`, `docs` and `scripts`
  passed, and so did the release's tests. The macOS builds never started
  (`macos-14` retired), so there is no v0.1.6 release; the fix
  (`macos-latest`, and `actions/checkout@v5` for GitHub's Node 20
  deprecation warning) goes out with v0.1.7.
- **macOS** binaries are built but still never run on a Mac, and they are
  not signed: the first run needs `xattr -d com.apple.quarantine lore`.
  Homebrew avoids that, once the tap exists.
- **zsh and fish completions** are untested: neither shell is on the build
  machine.
- **The AUR build file and the Homebrew formula** have not been built on
  Arch or by `brew`.
- **The `.deb` has an empty `Depends:` line.** apt accepts it; cargo-deb
  writes it for a static binary even with `depends = ""`. The 0.1.5
  record says it was fixed; it was not.
- **crates.io:** `publish = false` still holds. The name `lore-tui` is
  free there.
- **INTERNET** depends on cht.sh staying up and plain-text for curl-like
  clients.
- **Recipes'** steps were written carefully but not all run.
- **Carried from 0.1.5:** copying checked through tmux only, rough zsh
  history without `EXTENDED_HISTORY`, FILES listing paths that may not
  exist here, the logo crowding narrow terminals, and the thin man-based
  pages.
